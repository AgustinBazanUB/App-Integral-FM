<json-de-diseno>
El siguiente JSON forma parte integral y obligatoria de esta especificación.

No debe tratarse como una referencia secundaria, una sugerencia estética ni un archivo decorativo. Es la fuente de verdad del sistema visual para toda la superficie privada de gestión de Flor Mía y para cualquier pantalla administrativa nueva que se construya.

Nombre del sistema visual:
Flor Mia Natural Rustic Modern Design System

Objetivo visual:
Crear una aplicación administrativa natural, refinada, rústica contemporánea, premium sobria, editorial cálida, limpia e intuitiva, con inspiración mendocina sutil.

### Jerarquía de aplicación

Aplica las fuentes del proyecto en este orden:

1. Este JSON define el diseño de la aplicación privada y de todos sus módulos administrativos.
2. El repositorio `flor-mia-web-fiel-v3` define y conserva el diseño aprobado de la página pública y ecommerce.
3. El repositorio `FM-stock-y-ventas` aporta la lógica funcional existente del módulo de Ubicaciones, pero su interfaz debe migrarse progresivamente al sistema visual de este JSON.
4. Los requisitos funcionales, de seguridad y accesibilidad tienen prioridad cuando exista un conflicto imposible de resolver visualmente.
5. No sustituyas este sistema por un dashboard genérico, Material Design, Bootstrap, una plantilla SaaS prediseñada ni estilos por defecto de librerías.

### Reglas obligatorias de implementación

Antes de construir pantallas:

1. Analiza todo el JSON.
2. Convierte los valores reutilizables en design tokens.
3. Implementa variables CSS globales.
4. Crea una capa temática reutilizable.
5. Crea componentes base antes de construir módulos.
6. Mantén el mismo lenguaje visual en los 12 módulos.
7. Documenta cualquier excepción.
8. No copies contenido, entidades ni datos de las imágenes o referencias que originaron el JSON.
9. Usa solamente el estilo visual especificado.
10. Mantén la aplicación mobile first y accesible.

### Tokens y arquitectura visual

Implementa como mínimo:

- Colores de marca.
- Colores de fondo.
- Superficies.
- Colores de texto.
- Bordes.
- Estados semánticos.
- Paleta de gráficos.
- Gradientes.
- Tipografías.
- Escala de espaciado.
- Radios.
- Sombras.
- Texturas.
- Layout.
- Responsive.
- Motion.
- Accesibilidad.
- Estados hover, active, focus, disabled, loading, success y error.

Centraliza los tokens en una estructura equivalente a:

- `src/styles/tokens.css`
- `src/styles/theme.css`
- `src/styles/globals.css`
- `src/styles/responsive.css`
- `src/design-system/`

También puedes utilizar TypeScript o JavaScript para exportar tokens destinados a gráficos y componentes, pero CSS debe seguir siendo la fuente visual principal para evitar inconsistencias.

### Identidad visual obligatoria

La interfaz administrativa debe utilizar principalmente:

- Blanco cálido.
- Crema mineral.
- Dorado satinado.
- Madera oscura en zonas editoriales controladas.
- Verde oliva como apoyo semántico.
- Tipografía serif editorial para títulos y valores destacados.
- Tipografía sans serif funcional para formularios, tablas, navegación y datos.
- Sombras difusas y suaves.
- Bordes de baja intensidad.
- Alto espacio negativo.
- Decoración botánica lineal de baja opacidad.

No utilizar:

- Fondos oscuros dominantes en toda la administración.
- Dorado en todos los elementos.
- Verde oliva como CTA primario.
- Colores saturados no incluidos.
- Gradientes excesivos.
- Sombras duras.
- Glassmorphism dominante.
- Neomorphism.
- Tipografías manuscritas en controles o tablas.
- Emojis como iconos funcionales.

### Layout principal obligatorio

Desktop:

- Sidebar persistente.
- Header sticky.
- Área principal clara.
- Grid de 12 columnas.
- Tarjetas y paneles con radio principal de 14 px.
- Separación predominante de 16 px.
- Navegación activa dorada.
- Contenido sin ancho máximo artificial cuando las métricas o tablas necesiten espacio.

Tablet y mobile:

- Sidebar convertido en drawer.
- Una sola columna cuando sea necesario.
- Tablas transformadas en tarjetas apiladas.
- Controles táctiles de al menos 44 × 44 px.
- Botones principales de ancho completo cuando mejore la operación.
- Sin scroll horizontal, salvo matrices imposibles de reestructurar.
- Filtros dentro de panel o sheet colapsable.
- Priorización de contenido operativo.

### Aplicación por módulo

El mismo sistema visual debe adaptarse semánticamente:

- Ubicaciones: iconografía de mapa, tienda, calendario y vendedor.
- Ventas rápidas: carrito, recibo, métodos de pago y confirmación.
- Clientes fidelizados: usuarios, historial, etiquetas y seguimiento.
- Métricas: gráficos con la paleta especificada.
- Finanzas: valores tabulares, comparaciones, ingresos y egresos.
- Depósito: cajas, movimientos, transferencias y alertas.
- Ecommerce: catálogo, pedidos, publicación y stock web.
- Redes sociales: conversaciones, oportunidades y estados.
- Marketing: calendario, campañas, contenido y resultados.
- Envíos: ruta, estado, responsable y seguimiento.
- Alertas: severidad acompañada por icono y texto.
- Proveedores: compras, costos, productos y recepción.

### Iconografía

Utiliza Lucide React como biblioteca principal.

- Iconos lineales.
- Extremos redondeados.
- Grosor visual consistente.
- Sin mezclar bibliotecas salvo necesidad justificada.
- Todo botón compuesto únicamente por un icono debe tener `aria-label`.
- No usar emojis como reemplazo de iconos.

### Gráficos

Utiliza la paleta y reglas del JSON.

Los gráficos deben:

- Tener fondo blanco.
- Usar dorado como serie principal.
- Usar oliva para resultados positivos.
- Usar rojo apagado para valores negativos.
- Incluir tooltip.
- Incluir leyenda.
- Incluir resumen textual accesible.
- No depender exclusivamente del color.
- Reducir etiquetas en mobile.
- Evitar animaciones cuando no sean visibles.
- Respetar `prefers-reduced-motion`.

### Animaciones

Las animaciones deben ser fluidas, breves y funcionales.

Usar principalmente:

- `transform`
- `opacity`
- cambios de color
- cambios de sombra

Evitar:

- Rebotes.
- Destellos.
- Rotaciones decorativas extensas.
- Movimientos grandes.
- Animaciones que retrasen una venta.
- Animaciones continuas innecesarias.

Aplicar los tiempos, curvas y desplazamientos indicados en el JSON.

### Accesibilidad

Cumplir WCAG 2.2 AA.

Obligatorio:

- Foco visible.
- Navegación por teclado.
- Orden de tabulación lógico.
- Skip link.
- Focus trap en modal y drawer.
- Restauración de foco.
- Labels programáticos.
- Mensajes asociados mediante `aria-describedby`.
- Live regions para cambios de estado.
- Resúmenes textuales de gráficos.
- Estados que no dependan solamente del color.
- Zoom de texto al 200 %.
- Respeto por movimiento reducido.
- Contraste mínimo especificado.
- Objetivos táctiles mínimos.

### Uso de librerías

Las recomendaciones del JSON no autorizan dependencias innecesarias.

Antes de incorporar una librería:

- Verifica si el proyecto ya posee una solución.
- Evalúa peso, mantenimiento y accesibilidad.
- Evita instalar una biblioteca completa para resolver un componente pequeño.
- Mantén Lucide React como sistema de iconos.
- Para gráficos, formularios, tablas, fechas o motion, selecciona únicamente lo que sea realmente necesario.

### Criterios visuales de aceptación

La implementación no será aceptable si:

- Parece una plantilla SaaS genérica.
- Ignora los tokens del JSON.
- Usa colores aproximados sin necesidad.
- Presenta estilos diferentes entre módulos.
- Conserva la interfaz antigua del módulo de Ubicaciones sin migrarla visualmente.
- Tiene tablas ilegibles en mobile.
- Depende del color para representar estados.
- Utiliza controles táctiles pequeños.
- Presenta animaciones excesivas.
- Tiene decoración botánica interfiriendo con datos.
- Reduce la legibilidad por priorizar estética.

La implementación será aceptable cuando:

- Toda la administración se perciba como una única aplicación.
- Los módulos compartan componentes y tokens.
- El dorado marque jerarquía sin saturar.
- Las pantallas densas continúen siendo claras.
- La experiencia mobile permita operar ventas rápidamente.
- La identidad de Flor Mía sea reconocible sin perder profesionalismo.
- El diseño sea fiel al JSON en colores, tipografía, espaciado, estados, responsive, accesibilidad y animación.
