# Versión 1.1 · Envío 5 · Ventas, descuentos, ticket y registro por ubicación

## Alcance

Este envío amplía la rama `version/v1.1-login-inicial` sin crear una aplicación nueva y sin tocar `main`.

Se modificaron cinco áreas conectadas:

1. Carga de stock dentro de Ubicaciones.
2. Venta actual del Panel Vendedor.
3. Descuentos, pagos y futura solicitud de ticket.
4. Persistencia de ventas, stock, movimientos y auditoría.
5. Registro y detalle de Ventas dentro de cada ubicación.

La fuente funcional de referencia continúa siendo `AgustinBazanUB/FM-stock-y-ventas`, especialmente `seller.js`, `discounts.js`, `payments.js`, `firebase-service.js`, `keyboard.js`, `offline-sales.js`, `locations.js`, `categories.js`, `utils.js` y `app.js`.

No se copió el HTML ni el CSS del sistema anterior. Se migró la lógica útil a los servicios, hooks y componentes React existentes.

### Riesgos detectados

- `seller.js` calculaba descuentos secuencialmente en el orden en que se agregaban; el nuevo requisito exige agrupar primero todos los fijos.
- Las ventas offline deben conservar exactamente los descuentos y la solicitud de ticket para que la sincronización sea idempotente.
- El stock visible en pantalla puede quedar desactualizado mientras el carrito está abierto; la transacción debe volver a leer Firestore.
- El historial de ventas puede crecer de forma indefinida; la vista por ubicación debe paginar.
- `Ventas rápidas` conserva una transacción heredada propia para datos adicionales como canal, DNI y entrega. Este envío no crea una tercera lógica ni la elimina de manera riesgosa. La futura unificación debe preservar esos campos antes de retirar `createQuickSale`.

## Descuentos

### Fuente única de cálculo

Toda la aplicación continúa utilizando:

`src/modules/locations/domain/discounts.js`

La función central es:

`calculateDiscountSummary(discounts, subtotal)`

No se calcula el total dentro de componentes diferentes.

### Orden obligatorio implementado

El algoritmo ahora es:

1. Validar subtotal.
2. Normalizar descuentos.
3. Separar descuentos de monto fijo.
4. Aplicar todos los fijos en el orden relativo en el que fueron recibidos.
5. Limitar el saldo mínimo a cero.
6. Tomar ese saldo como base porcentual.
7. Aplicar los porcentajes sucesivamente, conservando la lógica histórica de `seller.js` para varios porcentajes.
8. Calcular total final.

Ejemplo obligatorio:

- Subtotal: `$100.000`.
- Fijo: `$10.000`.
- Base porcentual: `$90.000`.
- Porcentaje: `10 % = $9.000`.
- Total final: `$81.000`.

El resumen devuelve además:

- `fixedDiscountTotal`.
- `percentageDiscountTotal`.
- `discountTotal`.
- `totalBeforeDiscounts`.
- `total`.

### Descuentos guardados

El vendedor ve exclusivamente descuentos que pasan `isDiscountAvailable`:

- activos;
- no eliminados;
- vigentes;
- habilitados por `enabledDiscountIds` de la ubicación;
- compatibles con rol, productos y categorías cuando existan restricciones.

Antes de confirmar una venta el servicio vuelve a leer los descuentos guardados en Firestore y vuelve a validarlos. No se confía sólo en la opción visible en pantalla.

### Descuento manual

Se incorporó al diálogo `Agregar descuento` con:

- Monto fijo.
- Porcentaje.
- Campo numérico único.
- Valor entero mayor a cero.
- Porcentaje máximo de 100.
- Permiso `useManualDiscounts`.
- Persistencia con `source: "manual"` y `discountId: "manual"`.

Los descuentos guardados se persisten con `source: "saved"`.

## Transacción de venta y stock

`createSellerSale` continúa utilizando `runTransaction`.

Dentro de la transacción:

1. lee la ubicación real;
2. verifica actividad;
3. lee el contador;
4. lee cada documento real de stock;
5. verifica que cada producto continúe habilitado;
6. compara `currentStock` real contra la cantidad;
7. rechaza el conjunto completo si falta una unidad;
8. crea/actualiza el contador;
9. crea un único documento de venta;
10. actualiza stock;
11. crea un movimiento por producto;
12. crea auditoría.

Nunca se confirma parcialmente.

Edición utiliza diferencias de cantidades y anulación devuelve el stock. Ambas operaciones mantienen movimientos y auditoría.

`Panel Vendedor → createSellerSale → sales/{saleId}`
