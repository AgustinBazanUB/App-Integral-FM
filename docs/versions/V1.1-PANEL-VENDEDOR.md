# Versión 1.1 · Envío 4 · Panel Vendedor

## Alcance

Este envío incorpora una superficie React específica para vendedores físicos en `/vendedor`, integrada con la autenticación, los permisos, las ubicaciones, el catálogo, el stock, los descuentos y las ventas de la aplicación integral. No se creó otra base de datos, otra colección de productos ni otro stock.

La referencia funcional obligatoria fue el repositorio `AgustinBazanUB/FM-stock-y-ventas`, especialmente el archivo completo `seller.js` y sus dependencias.

## Ubicaciones y permisos

`effectiveSellerLocations` es la función centralizada que calcula el alcance del usuario. Considera:

- perfil activo;
- permiso de acceso a ventas;
- rol administrador general;
- permiso `viewAllLocations`;
- `allowedLocationIds`;
- `assignedSellerIds` de cada ubicación;
- actividad actual mediante `isLocationActiveNow`;
- fechas operativas, pausas y baja lógica.

La interfaz y los servicios repiten la validación. Cambiar manualmente la URL o un estado local no concede acceso a una ubicación ajena.

## Integridad de ventas y stock

Alta, edición y anulación usan transacciones Firestore.

### Alta

La transacción:

1. vuelve a leer ubicación y stock;
2. valida actividad y producto habilitado;
3. rechaza faltantes de stock;
4. incrementa el contador;
5. crea la venta;
6. descuenta stock;
7. crea movimientos;
8. registra auditoría.

No se confirma parcialmente. Dos vendedores que intentan consumir el mismo stock compiten sobre documentos leídos por la transacción y Firestore reintenta o rechaza la operación.

### Edición

Se calcula la diferencia entre cantidades anteriores y nuevas. El stock se devuelve o descuenta según esa diferencia y se registra un movimiento `sale_edit` por producto afectado.

### Anulación

La venta cambia a `cancelled`, conserva todo su contenido y recibe usuario, fecha y motivo. Las unidades vuelven al stock mediante movimientos `sale_cancel`. Nunca se borra físicamente.

### Reglas

Las reglas vinculan cada modificación de stock del vendedor con:

- `lastSaleId`;
- `lastMovementId`;
- venta del mismo usuario y ubicación;
- movimiento creado en la misma transacción;
- stock anterior y nuevo coincidentes.

Un ajuste aislado o un identificador inventado es rechazado.

## Offline

Las operaciones sin conexión se guardan en IndexedDB y muestran explícitamente que todavía no están confirmadas en Firestore.

- Estado `pending` o `sync_error`.
- Reserva local de cantidades para reducir ventas offline incompatibles dentro del mismo dispositivo.
- Reintento automático al recuperar conexión y manual desde Pendientes.
- ID remoto determinístico para evitar duplicados.
- Una pendiente fallida no modifica stock remoto.
- La eliminación exige confirmación explícita.

### Límite honesto

Una venta offline no puede reservar stock frente a otro dispositivo desconectado. La sincronización vuelve a validar el stock real y puede rechazar la venta; en ese caso permanece pendiente con el error. No se presenta como confirmada.

## Funcionalidades modificadas con justificación

### Venta por encima del stock

El sistema anterior permitía continuar después de una advertencia cuando el stock cargado estaba agotado. No se conservó. La aplicación integral bloquea la venta para impedir stock negativo, inconsistencias simultáneas y diferencias difíciles de auditar.

### Descuento manual libre

El vendedor nuevo sólo utiliza descuentos maestros activos y habilitados para la ubicación. El descuento manual del sistema antiguo no se expone a un vendedor normal porque evitaría la administración centralizada. Puede incorporarse más adelante mediante un permiso explícito y auditoría reforzada.

### Tiquet fiscal

El botón anterior era un placeholder sin integración fiscal real. No se muestra como función operativa confirmada. La venta genera un recibo interno en pantalla; la emisión fiscal continuará pendiente hasta definir proveedor y credenciales.

### Edición offline

No se permite editar una venta ya confirmada sin conexión. La edición necesita releer venta y stock para calcular diferencias seguras.

## Diseño y responsive

El panel utiliza tokens, tipografías y componentes de Flor Mía:

- blanco cálido, crema y dorado;
- texto oscuro y verde oliva para estados positivos;
- iconos Lucide React;
- bordes suaves, sombras bajas y radios consistentes;
- catálogo más compacto que el panel administrativo;
- carrito visible en desktop;
- confirmación persistente en mobile;
- controles de al menos 44 px;
- grillas adaptativas para 1440, 1200, 1024, 768, 480, 390 y 360 px;
- sin `100vw` ni contenedores que introduzcan scroll horizontal general;
- modales reutilizados con Escape, focus trap y restauración de foco.
